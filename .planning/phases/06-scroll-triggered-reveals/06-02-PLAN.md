Create a new file `src/app/[locale]/(landing)/_components/scroll-progress-bar.tsx` with the following content:

```typescript
'use client';

import { useRef } from 'react';
import { useGSAP } from '@gsap/react';
import { gsap, ScrollTrigger } from './gsap-registration';

export function ScrollProgressBar() {
  const barRef = useRef<HTMLDivElement>(null);

  useGSAP(() => {
    const mm = gsap.matchMedia();

    mm.add('(prefers-reduced-motion: no-preference)', () => {
      if (!barRef.current) return;

      gsap.fromTo(
        barRef.current,
        { scaleX: 0 },
        {
          scaleX: 1,
          ease: 'none',
          scrollTrigger: {
            trigger: document.documentElement,
            start: 'top top',
            end: 'bottom bottom',
            scrub: 0.3,
          },
        }
      );
    });
  });

  return (
    <div
      ref={barRef}
      className="h-scroll-progress"
      aria-hidden="true"
    />
  );
}
```

**Key design decisions:**

1. **`gsap.fromTo()`** ensures both the start (scaleX: 0) and end (scaleX: 1) values are explicitly set. This prevents any flash where the bar might briefly show at full width before GSAP takes control.

2. **`scrub: 0.3`** means the bar position smoothly catches up to the actual scroll position with a 0.3s lag. This prevents the bar from feeling jittery on fast or inconsistent scroll inputs. It feels natural and polished.

3. **`ease: 'none'`** makes the scaleX value proportional to scroll position -- 50% scroll = 50% bar width. No easing means the bar accurately represents scroll progress.

4. **`trigger: document.documentElement`** uses the root HTML element as the scroll trigger. Combined with `start: 'top top'` and `end: 'bottom bottom'`, this tracks the entire page scroll range. Since Lenis smooth scroll is synced to ScrollTrigger via `lenis.on('scroll', ScrollTrigger.update)` in SmoothScrollProvider, this automatically receives the correct scroll position.

5. **`gsap.matchMedia()`** gates the animation for reduced-motion users. The bar element still exists in the DOM but has `scaleX: 0` via CSS, so it's invisible. For reduced-motion users, no ScrollTrigger is created.

6. **`aria-hidden="true"`** marks the bar as decorative. It provides no semantic information and should not be announced by screen readers.

7. **No `scope` on `useGSAP`** -- the progress bar is self-contained and doesn't need to scope queries to a container. It only operates on its own ref.

**IMPORTANT:**
- Do NOT import `SplitText` -- it's not needed for this component.
- The component is intentionally minimal -- a single ref, a single tween, a single div.
- The `useGSAP` hook handles cleanup automatically on unmount (kills the ScrollTrigger).

**Key CSS decisions:**

- `height: 3px` is thin enough to be subtle but visible against the off-white background.
- `background: var(--hm-gold)` (#9E7C38) uses the project's gold accent color.
- `transform-origin: left center` ensures scaleX grows from the left edge.
- `transform: scaleX(0)` starts the bar at zero width (CSS default, before GSAP takes over).
- `z-index: 101` sits above the nav (`z-index: 100`). The nav is a floating capsule at `top: 20px`, so the thin 3px line at `top: 0` doesn't visually interfere.
- `pointer-events: none` prevents the bar from intercepting clicks on anything near the top edge.

  <action>
Restructure the FAQ HTML and CSS to use the sibling pattern for smooth open AND close animations via `grid-template-rows: 0fr -> 1fr`.

**1. Restructure FAQ HTML in page.tsx.** Replace each FAQ item from:
```tsx
<details className="h-faq-item">
  <summary>Question<span className="h-faq-chevron" aria-hidden="true" /></summary>
  <p>Answer text</p>
</details>
```
To:
```tsx
<div className="h-faq-item">
  <details className="h-faq-toggle">
    <summary>
      Question
      <span className="h-faq-chevron" aria-hidden="true" />
    </summary>
  </details>
  <div className="h-faq-body" aria-hidden="true">
    <div className="h-faq-body-inner">
      <p>Answer text</p>
    </div>
  </div>
</div>
```

Do this for ALL 4 FAQ items. Preserve exact question and answer text.

**IMPORTANT accessibility detail:** Add `aria-controls` and `id` attributes for screen reader association:
- Each `<summary>` gets `aria-controls="faq-answer-{n}"` (where n is 1-4)
- Each `.h-faq-body` gets `id="faq-answer-{n}"`
- The `aria-hidden` on `.h-faq-body` is a visual hint; the actual visibility is controlled by the grid animation

**2. Update CSS selectors in landing-home.css.** Migrate the FAQ styles:

**Keep unchanged:**
- `.h-faq` (container grid)
- `.h-faq-chevron` styles (the chevron itself)

**Change `.h-faq-item`** -- now a wrapper `<div>`, not `<details>`:
- Keep: background, border, border-radius, padding, transition, hover styles
- Remove: `[open]` selector on `.h-faq-item` (details-specific)
- Add: the `[open]` state is now on the inner `.h-faq-toggle`

**Change `.h-faq-item[open]`** to `.h-faq-item:has(.h-faq-toggle[open])`:
- This uses `:has()` to check if the inner details is open
- Baseline 2023 -- Chrome 105+, Safari 15.4+, Firefox 121+
- Drives border-color change on the wrapper

**Change `.h-faq-item summary`** to `.h-faq-toggle summary`:
- Same styles, just re-scoped to the new element

**Change `.h-faq-item[open] .h-faq-chevron`** to `.h-faq-toggle[open] .h-faq-chevron`:
- Same rotation transform

**Change `.h-faq-item[open] .h-faq-chevron::before`** to `.h-faq-toggle[open] .h-faq-chevron::before`:
- Same border-color change

**Remove `.h-faq-item p`** and replace with `.h-faq-body-inner p`:
- Same styles (margin-top, color, line-height, font-size)

**Add new accordion animation styles:**
```css
/* Accordion body -- grid-template-rows animation */
.landing-scope .shell .h-faq-body {
  display: grid;
  grid-template-rows: 0fr;
  transition: grid-template-rows 300ms var(--hm-ease);
}

.landing-scope .shell .h-faq-body-inner {
  overflow: hidden;
}

/* When sibling details is open, expand */
.landing-scope .shell .h-faq-toggle[open] + .h-faq-body {
  grid-template-rows: 1fr;
}
```

**Add `.h-faq-toggle` base styles:**
```css
.landing-scope .shell .h-faq-toggle {
  /* Reset details element */
}
```
The `<details>` element may have default padding/margin from browsers. Ensure it inherits cleanly.

**3. Update the summary marker suppression** -- change `.h-faq-item summary::-webkit-details-marker` to `.h-faq-toggle summary::-webkit-details-marker`.

**4. Add reduced-motion override** in landing-animations.css:
Inside the `@media (prefers-reduced-motion: reduce)` block:
```css
.landing-scope .shell .h-faq-body {
  transition: none !important;
}
```

**5. Verify the close animation works:** The key insight is that the `<details>` element still controls the `[open]` attribute. When the user clicks summary to close, the browser removes `[open]`. Because the animated content is in a SIBLING div (not inside `<details>`), the browser does NOT hide it. The CSS transition from `1fr` to `0fr` runs smoothly. This is the entire reason for the sibling pattern.

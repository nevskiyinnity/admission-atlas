## Tasks

<task id="09-01-A" title="Remove redundant CSS hm-fadeUp animations" estimated_minutes="3">

### Context

Five CSS selectors in `landing-home.css` have `animation: hm-fadeUp 700ms ...` declarations that fire on paint, but GSAP HeroEntrance and AnimatedSection already handle these elements' reveal choreography. The CSS animation completes at 700ms before GSAP fires, creating redundancy. The CSS initial states in `landing-animations.css` (opacity:0, translateY:24px) must remain untouched -- they prevent FOUC.

### Steps

1. Open `src/app/[locale]/(landing)/landing-home.css`

2. Remove `animation` and `animation-delay` lines from these 5 selectors:

   **a) `.landing-scope .shell .h-badge`** (~line 223-224):
   - Remove: `animation: hm-fadeUp 700ms var(--hm-ease) both;`
   - Remove: `animation-delay: 100ms;`

   **b) `.landing-scope .shell .h-hero h1`** (~line 235-236):
   - Remove: `animation: hm-fadeUp 700ms var(--hm-ease) both;`
   - Remove: `animation-delay: 200ms;`

   **c) `.landing-scope .shell .h-hero-desc`** (~line 250-251):
   - Remove: `animation: hm-fadeUp 700ms var(--hm-ease) both;`
   - Remove: `animation-delay: 300ms;`

   **d) `.landing-scope .shell .h-hero-actions`** (~line 258-259):
   - Remove: `animation: hm-fadeUp 700ms var(--hm-ease) both;`
   - Remove: `animation-delay: 400ms;`

   **e) `.landing-scope .shell .h-metrics`** (~line 369-370):
   - Remove: `animation: hm-fadeUp 700ms var(--hm-ease) both;`
   - Remove: `animation-delay: 500ms;`

3. After removing all 5 usages, search the entire file for any remaining reference to `hm-fadeUp`:
   - If ZERO references remain, also remove the `@keyframes hm-fadeUp { ... }` definition
   - If any reference remains, keep the keyframe definition

4. **DO NOT** remove or modify:
   - The `@keyframes hm-slideDown` definition (used elsewhere, not redundant)
   - Any CSS initial states in `landing-animations.css` -- those are a SEPARATE concern
   - Any breathing mesh animations, SVG accent animations, or glow animations

### Acceptance

- `grep -c "hm-fadeUp" landing-home.css` returns 0 (or only the @keyframes definition if other selectors still use it)
- The CSS initial states in `landing-animations.css` are unchanged
- `hm-slideDown` keyframe and all other animations are untouched

</task>

<task id="09-01-B" title="Audit animated properties and verify cleanup coverage" estimated_minutes="3">

### Context

PERF-02 requires all animations use compositor-friendly properties only. PERF-03 requires useGSAP cleanup on all components. The research audit found everything clean, but this task performs the definitive verification and documents the two accepted exceptions.

### Steps

1. **Compositor property audit** -- Search all animation-related code and verify properties:

   Search `landing-home.css` for all `@keyframes` blocks and `transition:` declarations. For each, verify the animated property is one of: `transform`, `opacity`, `clip-path`, `filter`. Document findings.

   Search all client component files for GSAP `.from()`, `.to()`, `.set()`, `.fromTo()` calls. Verify animated properties are: `y`, `x`, `opacity`, `scale`, `scaleX`, `clipPath`, `rotationX`, `rotationY`, `rotation`, `autoAlpha` (all compositor-friendly).

   Client components to check:
   - `src/app/[locale]/(landing)/_components/hero-entrance.tsx`
   - `src/app/[locale]/(landing)/_components/animated-section.tsx`
   - `src/app/[locale]/(landing)/_components/scroll-progress-bar.tsx`
   - `src/app/[locale]/(landing)/_components/magnetic-button.tsx`
   - `src/app/[locale]/(landing)/_components/tilt-card.tsx`
   - `src/app/[locale]/(landing)/_components/smooth-scroll-provider.tsx`

2. **Document accepted exceptions** -- Add a comment block at the top of `landing-animations.css` (after the existing header comment) documenting:
   ```css
   /* ── Compositor Property Exceptions (Phase 9 audit) ──
      Two non-compositor properties are used and accepted:
      1. background-position (breathing gradient meshes on ::before/::after pseudo-elements,
         15-25s animation cycles, paint-only — no layout trigger, decorative only)
      2. grid-template-rows (FAQ accordion transition, fires only on user click,
         standard CSS-only height animation pattern — no scroll-linked usage)
      All scroll-linked and entrance animations use transform/opacity/clip-path only. */
   ```

3. **Verify useGSAP cleanup** -- Read each of the 6 client components and confirm:
   - Components using `useGSAP` have `{ scope: containerRef }` or equivalent
   - MagneticButton and TiltCard return cleanup functions from matchMedia callbacks that remove event listeners
   - SmoothScrollProvider's useEffect returns cleanup that calls `lenis.destroy()` and removes ticker

4. **Verify reduced-motion completeness** -- Confirm `landing-animations.css` reduced-motion block covers:
   - All section types (hero children, orbs, metrics, sect, dark-sect, callout, final)
   - Breathing meshes (hero::before, callout-inner::after, final::before)
   - SVG accents, dark glows
   - SplitText word wrappers (h1 div, h2 div)
   - Scroll progress bar
   - FAQ transition

### Acceptance

- All GSAP-animated properties are confirmed compositor-friendly
- Two exceptions documented with clear justification in `landing-animations.css`
- All 6 client components confirmed clean for useGSAP/useEffect cleanup
- Reduced-motion block confirmed complete with zero gaps
- No new files created -- documentation added as CSS comments

</task>

   - Fix identified issues and re-run Lighthouse to confirm >= 90.

<task id="09-02-B" title="Restraint review and lazy-init documentation" estimated_minutes="4">

### Context

The "2-4 hero moments" rule ensures the page feels like a premium product, not a CodePen demo. Every non-hero animation should feel like natural physics. PERF-04 requires lazy-loading of animation code for below-fold sections -- the current architecture already does this via ScrollTrigger's deferred tween creation, which needs to be documented.

### Steps

1. **Restraint review** -- Mentally walk through the full page scroll and identify the hero moments vs. supporting animations:

   **Hero moments (keep prominent):**
   1. Hero entrance sequence (orbs + SplitText headline + spring CTAs)
   2. Dark outcomes section atmosphere (gradient bleeds + glows)
   3. Scroll-triggered heading reveals (SplitText clip-path on h2s)
   4. Magnetic button pull (on primary CTAs)

   **Supporting animations (should feel invisible/natural):**
   - Section fade-up entrances (AnimatedSection)
   - Parallax drift on decorative elements
   - Card tilt on bento grid
   - Scroll progress bar
   - Breathing gradient meshes
   - SVG accent rotations

   For each supporting animation, verify it does NOT draw attention to itself. Specifically check:
   - Section fade-ups: `duration: 0.8, y: 24` -- subtle, good
   - Parallax: `y: -25 to -18` range -- subtle, good
   - Card tilt: `max 4-5 degrees` -- subtle, good
   - Progress bar: 3px height -- subtle, good

   **If any supporting animation feels flashy or draws attention:**
   - Reduce its duration (e.g., 0.8s -> 0.6s)
   - Reduce its amplitude (e.g., y:24 -> y:16, or parallax range)
   - Add a comment explaining the restraint adjustment

2. **Document lazy-initialization for PERF-04** -- Add a documentation comment in `animated-section.tsx` near the useGSAP hook explaining the lazy pattern:

   ```typescript
   // PERF-04: Lazy animation initialization
   // ScrollTrigger defers tween creation until the section approaches the viewport
   // (triggered at 85% from top via 'top 85%'). No animation code executes for
   // below-fold sections until the user scrolls near them. The GSAP bundle itself
   // is shared across all components via the singleton registration in gsap-registration.ts,
   // making per-section code-splitting counterproductive (adds async complexity for
   // negligible bundle reduction since GSAP is the heavy dependency, loaded once).
   ```

3. **Final reduced-motion end-to-end check** -- Verify the complete chain works:
   - `landing-animations.css` sets initial states (opacity:0, translateY:24px)
   - `landing-animations.css` reduced-motion block overrides with `!important` (opacity:1, transform:none, animation:none)
   - All GSAP code is gated behind `gsap.matchMedia()` with `(prefers-reduced-motion: no-preference)`
   - Result: reduced-motion users see full content immediately, zero FOUC, zero animation

   If any gap is found in this chain, fix it.

### Acceptance

- Hero moments identified and confirmed (2-4 cinematic moments)
- All supporting animations verified as subtle/natural
- Any flashy non-hero animations have been toned down with explanatory comments
- PERF-04 lazy-init documentation comment added to `animated-section.tsx`
- Reduced-motion chain verified end-to-end with zero gaps
- No new animation code added (this is an audit phase, not a feature phase)

</task>
